## Why Consistency Matters

I think this is excessive, but it's what you need to do to become more special than other college students. You only need to apply a minimum of 30 minutes into Codeforces every day.

**Consistency is key.**

## The Daily Rules

Here are the Codeforces everyday rules:

### 1. **Rating + 200**
Only solve problems rated +200 from your current rating.
- If you solve it under 15 minutes → too easy
- If you can't solve it in 2 hours → too hard

### 2. **Architectural Solution**
After solving a problem, refactor it. Apply clean code principles to build the muscle of writing high-quality code under time pressure.

### 3. **Upsolving**
This is non-negotiable. Always solve all problems from your previous contests, this is where the real growth happens.

### 4. **2-Minute Rule**
If you don't feel like coding, commit to just reading the problem statement for 2 minutes. Often this is enough to get started.

### 5. **Mistake Diary**
Document why you failed:
- Logic error?
- Knowledge gap?
- Implementation bug?

## The Upsolving Process

When upsolving, follow these steps:

### 1. **Document Your Upsolve Queue**
Markdown is fine for documenting your solutions alongside version control. There are interesting ways to automate this, I'll discuss details later. Basically, it uses the Codeforces API to automatically list problems from your last contest where you didn't get AC status.

### 2. **60-Minute Wall**
Do not look at the editorial or other code until you've spent at least 60 minutes of active thinking.

### 3. **Architectural Review**
After you solve the problem, look at the top-rated solution. Analyze their code structure and approach.

### 4. **Two-Pass Method**
1. Read the hint in the editorial first
2. Try to code it again based only on the hint
3. If you still fail, read the full tutorial
4. If the tutorial is unclear, look at the source code

## Important Reminders

Pay attention to these three principles:

1. **You Don't Understand It Yet**  
   When you read a solution and think "I understand it now", **no you don't**. You only truly understand it once you've implemented it from scratch without looking back at the tutorial.

2. **Keep It Simple**  
   A simple markdown documentation is good enough. Don't over-complicate it.

3. **Learn the Algorithm, Not the Style**  
   Don't emulate red coder style. Emulate their algorithmic efficiency instead.
